# Recipe: the logs kit

## What it answers

What a log file or a folder of log files says: which kinds of error there are and which happen most, whether one is new in a window, when a text or an error first appeared and how often since, what happened around a time, a line or a request id across several logs, how the rate of entries and errors changed over time, what an access log shows by status, path and time, and how two logs or two periods differ. It does not act: it only reads.

## What it needs

- Node.js 22.13 or newer. No packages, no programs.
- ask-kit with kit support (`min_ask_kit = "0.3.0"`).
- Settings, all optional: `WORKDIR` (detected as the folder the agent runs in), `LOGS_DIRS` (where to look when no log is named; default `logs` and `log` under `WORKDIR`, and `/var/log` on Linux and macOS), `LOGS_UTC_OFFSET` (the zone of timestamps written without one; default UTC). No tokens.

## What it reads and runs

It reads files with `node:fs` and `node:zlib` as a stream, a chunk of 1 MB at a time: the files the caller names, or the log files found by name in the `LOGS_DIRS` folders (`*.log`, `*.log.*`, `*.out`, `*.err`, `*.jsonl`, `*.ndjson`, names with `log` in them; three folders deep, at most 20000 directory entries, hidden folders and `node_modules` skipped). It runs no program and writes nothing. It keeps no state on disk.

Formats, detected per file from its first 64 KB and said in every result: JSON lines (time, level, message and error found among the usual field names), logfmt, syslog (RFC 3164 and 5424), common and combined web access logs (with nginx's request time when it is the last field), text that starts with a time (Python logging, Java and log4j, Go, Rust tracing, nginx and Apache error logs, PostgreSQL), text with a time near the start of the line, Python's `LEVEL:name:message`, npm debug logs, and plain lines. Timestamps: ISO 8601, `2026-11-08 21:00:03,123`, `2026/11/08 21:00:03`, syslog's `Nov  8 21:00:03` (year from the file's modified time), `[08/Nov/2026:21:00:03 +0000]`, `Sun Nov 08 21:00:03 2026`, epoch seconds and milliseconds. A time without a zone is read as UTC unless `LOGS_UTC_OFFSET` says otherwise. A line without a time belongs to the entry above it; in a file where fewer than half the lines start with a time, such a line is an entry of its own unless it is indented or part of a stack trace. Gzip is recognised by its first bytes. Files packed with xz, bzip2 or zstd are not read.

Hidden because answers go to a cloud model: the values after `password`, `passwd`, `pwd`, `secret`, `token`, `api_key`, `access_key`, `private_key`, `credential`, `authorization`, `cookie`, `session_id` and `signature` keys (with `=` or `:`, in text, in URL queries, in JSON fields, in JSON inside text), `Authorization`, `Cookie`, `Set-Cookie`, `X-Api-Key` and `X-Auth-Token` headers, `Bearer` and `Basic` values, the password of a URL, private key blocks, and JWT, GitHub, OpenAI-style, AWS and Slack token shapes. Redaction happens before a line is parsed, so signatures and `grep` see the redacted text. Refused by name: `.env`, `.npmrc`, `.netrc`, `.pgpass`, `.git-credentials`, `htpasswd`, `shadow`, `sudoers`, key files (`id_rsa`, `*.pem`, `*.key`, `*.p12`), `credentials.*`, `secrets.*`, shell histories, and anything under `.ssh`, `.aws`, `.gnupg`, `.kube` or `.docker`.

Bounded: a call stops reading after 100 seconds and says how far it got; a line is cut at 64 KB; an entry keeps 60 lines of stack trace and counts the rest; at most 5000 kinds are grouped; `scan` returns 50 entries by default and 500 at most; `around` 60 and 200; `overview` reads 512 MB in all for its counts and lists the rest without them; messages are clipped at 400 characters and field values at 160.

## Brief to rebuild it from an empty folder

Make a folder with `ask-kit.toml` (id `temet.logs`, name `logs`, `says`, `keywords`, `route_hint`, `cite`, no `acts`, three `[[settings]]`: `WORKDIR` with `detect = ["node", "-e", "process.stdout.write(process.cwd())"]`, and `LOGS_DIRS` and `LOGS_UTC_OFFSET` with `default = ""`; one `[[sources]]` of kind `module`, name `logs`, module `logs.mjs`, api `api.d.ts`; `instructions = "instructions.md"`; two reading `[[actions]]`: `files` on the `overview` script for "what log files are here", `errors` on the `errors` script for "what errors are in X.log").

`parse.mjs` has no file access. It holds: the level names and their spellings (text, pino numbers, syslog severities); the timestamp readers, each a sticky regex and a function to epoch milliseconds, with a fast path for `2026-11-08T21:00:03.123Z`; `detect(lines, ctx)`, which tries JSON, access, syslog 5424, logfmt, then the kind of time most lines start with, then the formats without a time, and returns a label and a factory for the line parser; one parser per format, each returning `{t, level, msg, obj?}` for an entry or `null` for a line that continues the entry above; `redact(text)` and `redactValue(json)`, behind a cheap test of three regexes (one regex with every alternative in it reads four times slower); and `signature(text)`. The signature takes the first line and replaces, in this order: URLs (host kept, path as a pattern), UUIDs, timestamps, quoted values (a quoted sentence of four words or more is kept), email addresses, IP addresses, the segments of a path that hold digits, hex numbers and long ids, durations, sizes, the values of id-like keys, and at last every number, except a number after `status`, `code`, `errno`, `exit`, `signal` and codes such as `E404`, `TS2345` and `ORA-00942`. A stack trace adds the line that names the exception: the last line of a Python traceback, the first exception line otherwise.

`logs.mjs` exports `make({settings, push})` returning the `logs` global. Inside: `info(path)` reads the first 64 KB of a file once per modified time (gzip, encoding, format, first time); `readLines` streams a file through `StringDecoder`, splits on newlines and stops at the time limit; `assembler` redacts a line when the cheap test hits, parses it, joins continuation lines to the entry above and drops the lines of a private key; `resolve(file)` turns a path, a folder, a name or part of one, a list, or nothing into logs, where the files of a rotated set (same name after `.gz`, `.N` and date suffixes are removed) form one log ordered by first time; `when(arg)` reads a time argument, with `last` and `first` taken from the log; `seek` finds by bisection where a window starts in a plain file over 32 MB, checks that the probed times are in order, and counts the lines before it from raw bytes so line numbers stay true; `run(logs, query, fn)` walks the entries of a window. On top of `run`: `scan`, `each`, `errors` (a Map from signature to count, first, last, levels and one example; the signatures seen before the window decide `new`), `timeline` (buckets sized so the window has at most 48; the usual level is the lower quartile, and a stretch at three times it is marked high), `firstSeen` (a ring of the entries before the first match), `around` (a ring before and a countdown after each hit, per log, then merged by time), `requests`, `compare`, `overview`, `tail` (read from the end of the file) and `files`. Ordinary failures (no such file, not text, damaged gzip, permission denied) come back as `{error}` or in `notes`; only refusals, missing params and unreadable times, levels and regexes throw, and the message names the accepted forms.

Scripts in `scripts/` (each `export const meta = {purpose, params, returns, example}` and `export default async function ({logs}, params)`), each a call of the matching function with a one-line `verdict` put first: `errors`, `timeline`, `first-seen`, `around`, `requests`, `compare` (two files, or one file with `split`), `overview` (one line per log).

`instructions.md` has the same structure as the docker kit's: how to work (scripts first, `overview` when no file is named, never guess a file name, time arguments and when to count from the log's end, rotated sets, what a signature is, how to decide new, started, still happening and spike from the evidence, redaction and why, what belongs to other kits, failing cells, never guess), and the answer format (answer first, cite file, line number and timestamp).

`bench/questions.json` holds only `do` questions, run against `bench/fixture/`, which `bench/fixture/build.mjs` writes with fixed times and a seeded generator (Discworld logs: the clacks relay as JSON lines with an error that starts at 21:14:34, the Watch duty application as a Python log with a traceback and three lines of credentials, an nginx access log with a burst of 502, a semaphore tower's logfmt log as a rotated set with one gzipped part, a syslog file). Windows are counted from the log (`last-1h`, `21:14`), never from the wall clock. Run `ask-kit kit test logs` from the kit's folder, because relative paths resolve against `WORKDIR`. Model questions (`q`) are still to be added, from real sessions in which an agent read a log by hand with `tail`, `grep` and `awk`; ask-kit's rule is that they are never invented.

## Results

ask-kit `kit test` on 2026-11-21: 22/22 shots, all answered with no model. No model run has been made. On a generated 1 GB JSON-lines log of 5.6 million lines: `errors` over the whole file in 11 s (about 500000 lines a second), peak memory 135 MB, counts equal to `grep -c`; `timeline` of the last ten minutes in 0.7 s; a gzip file at about 380000 lines a second. Run on Linux only.
